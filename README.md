# JULIUS ZERO ROOM v0.15.1 CLOUD SYNC

## v0.15.1 移動後の実績表示・二重記録の修正

- RECOVERYの「記録済み」をサブスク含む全固定支出の実績へ修正。移動済みの10/5の購入もそのまま集計し、移動だけで実績額が減って見えないようにする。予定額は手動購入分と明記し、実績と区別する。
- サブスクカードに対象期間・記録済み/未記録・実際の支払日と金額を表示。記録済みなら「記録を見る・訂正」で既存の購入記録を開き、新しい購入を作らない。
- 重複防止を同じ日から同じ期間へ拡張。月額は購入日の暦月、年額は暦年、その他は契約の更新日を起点とした日数周期で判定。購入日を変えた新規保存、移動元ID経由、同期受信後の古い入力画面からの保存も検査する。
- 次の未記録期間の支払いは通常どおり記録できる。2端末で異なる購入日を入力しても、同じ契約・期間なら共通の新規購入IDを使用する。過去のIDは書き換えない。
- 既に複数ある記録は合計と件数を表示し、確認一覧から各記録を訂正できる。自動削除・自動統合はしない。
- 過去履歴、契約、同期方式、JSON形式、NO BUY・後払い・残高等の基本計算は維持。PC・スマホをともにv0.15.1へ更新する。旧v0.15.0との併用では同月別日の重複を防げない。

## v0.15 SUBSCRIPTIONS / 自動継続サブスク

- 05 SUBSCRIPTIONSへ自動継続契約を一度登録し、月をまたいで保持。月額換算・年間概算・ACTIVE件数・次回請求を表示し、ACTIVEは次回請求順に並べる。
- 毎月の更新日、年額の更新日、その他の日数周期（1〜3660日）に対応。存在しない月日は月末へ丸め、元の更新設定を保持。当日は当日の予定を表示する。その他周期の概算は365日基準。
- PAUSED / CANCELLEDは予定と合計から除外し、契約と支払い履歴を保持。実サービスの停止・解約を代行する機能ではない。
- 「支払いを記録」は既存PURCHASE LOGの下書きを開く。固定・デジタル・契約の支払い方法を初期入力し、当日を初期日付にする。金額・日付・支払い方法は実請求に合わせて変更し、最終保存は手動。更新日・契約保存・画面表示では購入記録を作らない。
- 支払いは通常の固定サービスとしてHISTORY / NEW AFTERPAY / MERPAY・PAIDY / 残高推定 / カレンダーSへ反映。NO BUYや趣味・衝動判定には混ぜない。同契約・同日の重複を防ぎ、同日記録済みのカード操作は訂正画面へ。2端末で同日を記録しても共通IDで二重加算を防止する。
- FIXED COMMITMENTSの固定サービスだけ、手動で更新日等を確認して移動できる。月パスを自動判定・移動しない。移動元の登録は互換性と過去記録のため保持し、明示的にリンクした項目だけ月別計画から除外。過去の購入履歴を変更しない。
- RECOVERYには月額相当と次回予定だけ参照表示し、MONTHLY REALITYの手持ち・必須支払いへ自動加算しない。HOMEの情報量は増やさない。
- subscriptionsコレクションを同じ本人UID限定のFirebase保存先へ追加。既存schemaVersion 7、保存キー、他コレクション、認証ルールを維持。JSONバックアップにも契約・支払いリンクを含める。
- 旧版のデータにはsubscriptionsVersion=0を持たせ、初めて新コレクションを読む時はクラウドの未読契約を保護。旧端末の新しい購入更新日時だけで、未知の契約を削除しない。同期前・送信中の契約作成も保持。既存の競合保護・削除マーカー・オフライン再送を再利用する。
- PC・スマホの両方をv0.15.0へ更新して使用する。旧版にはサブスク画面がない。更新のためにサイトデータを消す必要はない。
- 静的な説明は「？」内へ収納。LIGHT / DARK、PC / スマホの既存スタイルを再利用。

## v0.14 反動買い・高額支出 / JULIUS FEEDBACK

- 趣味・衝動買いだけの1日合計で、5千円／1万円／2万円／5万円の段階表示。カレンダーは通常¥、強調¥、赤い¥!、強い!、最強の!!へ変化する。必要品・固定分・注意支出は判定に混ぜない。
- DAILY LOGの先頭にHIGH SPEND DAYと、趣味・衝動合計・同区分の後払い・件数を表示。全区分合計と個別明細も維持。
- 新しい趣味・衝動購入の保存後、HOMEの折りたためるJULIUS FEEDBACKを開く。日合計、記録月のNEW AFTERPAY、状況別コメント、現在のGOAL FUNDとの比較を表示。訂正を新規購入として叱責しない。
- 直前の確認済みNO BUYが3日／5日連続、直近7日の見送りと高額購入から、反動買いの「可能性」を表示。未記録日はNO BUYと推測しない。
- IMPULSE CHECKへ7つの反動買いサインを追加し、強い重みで判定。高額購入済みの日は開いた時に当日合計を強調。
- HOLDの見送りは既存outcome=declinedのままCLOSED / 見送り終了と表示。現金確保後の再検討はoutcome=cash-reviewで終了し、STOPPED URGESや積立には加算しない。再検討は購入許可・現金確保済みという意味ではない。
- 24時間延長時だけextensionCountを増やし、3回以上で指摘。待機中の延長連打は無効。既存の訂正・取り消し・購入紐付けは維持。
- BIG SPEND DAYSは表示月の1日1万円以上の日数。NO BUYと見送り回数は購入権・報酬ではないことを明記。
- NEW AFTERPAYには「STOP LINE / ここから増やさない」の固定表示。任意金額の予算設定や残り利用可能額は作らない。
- 当月の後払いが前月記録額を超えた時にMONTHLY ALERT。同日数までの実績が上回る時だけ、折りたたんだSPENDING PACEを表示。前月記録がなければ比較せず、未記録分・将来額は推測しない。
- 返済そのものや他アプリの売却を推測しない。前回より減った残高スナップショット（3日内）や、売却分の積立記録（7日内）がある時だけ対応するコメントを表示する。
- データversion 7、Firebase保存先・認証・同期処理は維持。新しいHOLD項目は既存レコード内に保存し、古い記録を起動時に書き換えない。LIGHT / DARKの端末別設定も維持。
- PC・スマホの両方をv0.14.0へ更新してから新しいHOLDの結果を編集する。旧版はcash-reviewの表示に対応していない。

## v0.12 GOAL FUND / 目標積立

- 下部ナビへ04 GOAL FUNDを追加。初期UIは「AI・PC強化基金」1件。GPUなど特定の商品へ固定せず、目標額未設定でも使える。
- 実際に封筒・別口座・その他へ分けて確保した金だけ、手動で積立を記録する。通常積立、不用品売却、見送り分を実際に確保、臨時収入、その他の積立元を選べる。500／1,000／3,000円の入力補助は金額を入力するだけで保存しない。
- 現在積立は履歴の積立合計−取り崩し合計から算出。残高を別々に保存して二重加算しない。今月は暦上の当月の積立総額を表示し、取り崩し額と差し引きも明示する。小さい節目、任意目標額と達成率を表示する。
- 日付・種別・積立元・保管場所・メモを履歴へ保存し、訂正・削除にも対応。取り崩しは出入りの記録として扱い、失敗・ペナルティにしない。入力で残高を超える取り崩しは拒否する。別端末との同時記録などで履歴の残高が負になった場合も、0に隠さず実際の差し引きを表示する。
- 主な保管場所は新しい記録の初期選択へ反映する。設定変更で過去の履歴や金額は変わらない。実際の保管場所を移す際、同じ金を新しい積立として二重登録しない。
- 「欲しい！」の結果と「ジュリアス、止めろ」に現在積立を表示。候補金額を入力すると比率と「実際に確保した場合」の比較を表示。見送りやHOLD、購入記録からの自動積立は一切行わない。
- 基金画面・積立入力・比較表示に「返済を優先する。余剰現金だけを未来へ残す。」を表示。購入、後払い、NO BUY、MONTHLY REALITYの手持ちや返済額は自動変更しない。
- データはschemaVersion 7を維持。goalFunds（基金設定）とgoalFundTransactions（入出金）を追加し、既存の/users/{uid}/zeroroomV3/meta配下の同名コレクションへ記録単位で同期する。本人UID限定の既存ルールは維持。記録の更新日時、削除マーカー、通信エラー再試行、安全コピー、JSONバックアップにも含める。
- 自動検証：既存の集計・移行・購入・HOLD訂正に加え、積立と取り崩し、目標未設定、保管場所、月替わり、入力誤り、訂正・削除、古い操作の拒否、見送りの非加算、比較表示、保存・復元、基金だけの端末、オフライン復帰、2端末相当の同期。ブラウザでPC幅と320px／390px幅を確認。実機スマホとPCでのFirebase同時通信は未実施。

## v0.10 診断・緊急停止・HOLD（過去の変更）

- 「欲しい！」は商品名・金額（省略可）と28種類の危険サインを選ぶ簡易診断。4分類を折りたたみ、結果へ数字と最大3件の短い台詞を表示する。
- 通常サインは1点、特に強い6項目は2点。0～1点 LOW、2～3点 CAUTION、4～5点 HIGH、6点以上 VERY HIGH。購入許可を意味しない。希少性のサインには24時間HOLDを推奨。
- 「ジュリアス、止めろ」は入力不要の緊急停止。財務数値と8つの短い選択肢、条件別の複数台詞を表示する。商品名・金額は任意欄から残せる。
- 財務表示は暦上の今月が対象。今月のNEW AFTERPAY、MERPAY＋PAIDYの既存残高推定、翌月のMONTHLY REALITYに登録したMERPAY／PAIDY支払予定の合計を使う。残高と来月分は未登録を0円扱いしない。通常診断には今月のNO BUY、見送り回数、全購入区分の購入日数（同日重複なし）も表示する。
- HOLDは登録から10分または24時間。HOMEの「HOLDを確認」で残り時間と結果待ちを確認できる。期限が過ぎても自動加算せず、まだ欲しければ24時間延長、もういらなければ見送り、買った場合は購入済みとして閉じる。
- 「今回は買わない」またはHOLDの「買わなかったと確定／もういらない」で初めてSTOPPED URGESへ1回加算。連続タップや別端末の同じ結果は同じ記録IDで扱い、二重加算しない。見送りの月は確定日時の月。
- HOLDの「買った」はHOLDの結果だけを保存する。金額の二重計上を避けるため、購入履歴への自動追加はしない。未入力なら通常の「買った。記録する」から記録する。
- 既存stoppedUrges／Firebaseのurgesコレクションへoutcome、商品情報、危険サイン、開始・終了・確定日時を追加。新コレクションや権限変更は不要。過去の記録と過去に加算済みの回数は修正しない。schemaVersion 7、購入・残高・固定支出の計算とv0.9同期方式を維持。
- PCとスマホの両方をv0.10.0に更新して使用する。旧版は新しいHOLDと見送りの区別に対応していない。

## v0.7 注意支出と小さい後払い（過去の変更）

- 「買った。記録する」の購入区分にCAUTION SPEND / 注意支出を追加。選んだ場合だけSNACK / COMFORT FOOD、OPTIONAL DAILY GOODS、OTHER CAUTIONの3分類を表示する。
- 必要な食事・飲料、洗剤や衛生用品などの必需品は「必要な買い物」。お菓子・間食、任意の百均用品や便利グッズは注意支出。予定外の趣味物・追加課金は従来通り趣味・衝動買い。
- HOMEのCAUTION SPENDはカレンダー表示月の実支出合計。3分類の内訳も表示する。予算・残り利用可能額は作らない。
- 注意支出はNO BUYを自動解除しない。カレンダーはCバッジを追加し、固定分のS/Pと併記できる。趣味・衝動買いがあれば¥ + C、なければ✓ + C。薄い✓の段階では未確定で、NO BUY DAYSへの計上はDAILY CHECKで確定後。
- 注意支出／趣味・衝動買いでMERPAY／PAIDYを選ぶとPAYMENT WARNINGを表示。「それでも後払いとして記録する」で実際の後払いを保存できる。「今ある金から払うへ変更」は選択だけを変更し、通常の保存で確定する。既に後払いで支払った場合は、その事実を記録する。
- 必要品・固定分を含め、すべての区分の後払いをNEW AFTERPAY、MERPAY／PAIDY、残高の推定へ従来通り加算する。
- HOMEとREALITY CHECKへ、ポイント・クーポンで購入や後払いを正当化しない短い警句を追加。
- HISTORYから注意支出の金額・分類・日付・支払い方法を訂正／削除でき、月合計とバッジは元記録から再計算する。
- データはversion 7。購入のpurposeにcaution、cautionCategoryにsnack／optional-daily-goods／otherを保存する。v0.6以前の記録を名称から自動再分類しない。JSONと既存の記録単位同期で引き継ぐ。

## CLOUD DATA SIZE

- SETTINGS / SYNC内に表示。WORK ROOMの公開実装（cloud-sync.jsのgetSyncPayloadBytes）を参照し、JSON.stringifyしたデータをBlobにしてUTF-8バイト数を測る方式を再利用した。
- ZERO ROOMでは同期対象の6種の記録をrecordMapsでまとめて計算する。端末内の未送信分も含む。画像・ローカル設定・バックアップ・syncTests・削除マーカー・サーバー付加情報・Firestoreの索引は含まない。
- B／KB／MBを1024単位で切替。「ESTIMATED / 同期対象データの推定サイズ」と明記する。取得失敗はUnavailableと表示する。
- WORK ROOMの900 KB安全上限は単一文書方式専用。ZERO ROOMは記録単位で保存するため、その上限や残容量の表示は移植していない。Firebase全体の使用容量・請求対象量を表すものではない。
- 購入・固定登録・残高・MONTHLY REALITY・NO BUY等の保存、編集、削除、クラウド反映、同期完了、設定画面を開いた時に再計算する。サイズ確認のための追加通信は行わない。

## v0.14への更新

PC・スマホ双方で設定画面のv0.14.0を確認する。旧表示が残る時は、オンラインで一度開いた後に再読み込み、またはアプリを完全に閉じて開き直す。更新のために記録やサイトデータを削除する必要はない。

## 起動と保存

- WORK ROOMと同じ静的PWA構成。GitHub Pagesへそのまま配置できる。
- 画面と記録は端末内データから即時に開き、Firebaseの応答を待たない。
- オフライン中の変更は端末内の送信待ちキューへ保存し、再接続後に自動送信する。
- Firebaseが使えない場合も、端末内保存・JSON書き出し・読み込みは動作する。
- v0.4までの本番データは同じ保存キーから自動移行する。旧「今月の収入 / 給料」は新しい予定収入へ勝手に加算せず、再確認を一度案内する。
- 旧形式の後払いは支払い先を推測せず「旧：後払い先未設定」として残す。

## 維持する機能

- PC・スマホ間のGoogleログイン同期
- `days`、`purchases`、`urges`、`recovery`をID単位で個別同期
- 各記録に `createdAt` / `updatedAt` を保持
- 同時追加を失いにくいレコード単位の同期と削除マーカー
- 起動・再接続時に最終更新日時を比較し、自動採用
- `LOCAL` / `SYNCING` / `SYNCED` の小さな状態表示。通信エラーの詳細は設定内で確認
- 設定画面に最終同期時刻、未送信件数、キャッシュ状態を表示
- エラー時だけ「再試行」を表示
- DAILY LOGから手動でNO BUYを記録
- 必要品はNO BUY資格を失わず、必要品の後払いもNEW AFTERPAYへ加算
- TODAY STATUS、HOLD ACTIVE、RECOVERY、月別履歴、JSONバックアップ
- PWA、オフライン起動、端末内保存
- 月別のMONTHLY REALITYと、不足額を使うREALITY CHECK
- 新規後払いをMERPAY / PAIDYへ分離して集計
- CONFIRMED / NEW SINCE LAST CHECK / ESTIMATED（推定）の残高表示
- 購入記録・日別状態・残高スナップショットの編集と削除
- MONTHLY REALITYを含む編集可能データの `createdAt` / `updatedAt`
- 削除マーカーをクラウドへ残し、別端末で削除済み記録が復活しにくい同期
- ZERO ROOM専用の盾とゼロを組み合わせたPWAアイコン
- `CURRENT CASH + EXPECTED INCOME REMAINING` から今月利用可能額を算出
- 今月利用可能額から必須支払いを引き、予測不足額を「欲しい！！」と緊急停止へ反映
- `NEXT SALARY` は参考値として保持し、今月の計算から除外
- STOPPED URGESは累積、HOLD ACTIVEは翌日までという違いを明記
- スマホの購入記録画面とRECOVERY対象月入力の横幅を補正

## Firestore保存先

v0.9もv0.6以降の保存先を維持する。注意支出は既存purchasesへ保存する。

```text
users/{uid}/zeroroomV3/meta
  ├─ days/{YYYY-MM-DD}
  ├─ purchases/{purchaseId}
  ├─ urges/{urgeId}
  ├─ recovery/{snapshotId}
  ├─ reality/{YYYY-MM}
  └─ fixedCommitments/{fixedId}
```

初回だけ旧 `users/{uid}/zeroroom/state` を読み込み、内容があればv0.3形式へ移行する。旧データを即座に削除はしない。

同梱の `firestore.rules` は、本人のGoogle UID配下だけを読み書き可能にする最小ルールだ。既存プロジェクトの他アプリも同じ `/users/{userId}/{document=**}` 規則を使う場合は、そのまま共存できる。

## 公開時の確認

1. GitHub PagesなどHTTPSの公開先へ全ファイルを配置する。
2. Firebase AuthenticationでGoogleログインを有効にする。
3. 公開ドメインをAuthenticationの承認済みドメインへ追加する。
4. `firestore.rules` と同等の本人限定ルールを反映する。
5. PCでログインして記録し、スマホで同じアカウントへログインして反映を確認する。
6. 片方をオフラインにして記録し、再接続後に両端末へ反映されることを確認する。

ローカルファイルとして直接開いた場合、記録機能は使えるがGoogleログインとPWAは無効。クラウド同期確認にはHTTPSが必要だ。

## v0.6 固定支出のルール

- 購入区分は必要品／事前登録済み固定支出／趣味・衝動買い。既存記録は自動で固定扱いへ変更しない。
- RECOVERYで月別・項目別に名称、金額、FIXED SERVICE／FIXED GAME PASSを登録・編集・削除する。サンプル項目は勝手に登録しない。
- 月途中・過去月の追加、別月への移動、名称・分類の差し替えや増額は、事前の予定だったことを強く確認する。
- REGISTEREDとRECORDEDは事実の集計のみ。残り予算、転用、繰り越し、購入を促す通知は作らない。
- 購入画面では購入月の登録項目から選ぶ。同じ項目の二重記録を避け、金額訂正はHISTORYで行う。
- 固定だけの日は衝動PURCHASEにしない。S／Pバッジを表示し、NO BUYは従来通りDAILY CHECKで確定する。薄い✓は固定のみ記録された未確定日。
- 固定でもMERPAY／PAIDY、NEW AFTERPAY、NEW SINCE LAST CHECK、ESTIMATEDへ通常通り加算する。
- 固定登録額をCURRENT REQUIRED PAYMENTSへ自動加算しない。支払い時期が異なり、二重計上になるため。
- 記録済み状態は関連購入から毎回算出する。別端末での追加・編集・削除にも追従する。
- 登録項目を削除・別月へ移動しても、実際の購入日・支払額・記録時の分類は履歴に保持する。登録総額だけが変わり、過去の支出は消えない。
- 固定項目と購入の関連ID・記録時名称・分類はJSONバックアップ／Firebase同期に含む。
- 旧版で新しい固定購入を編集しないよう、PCとスマホの両方でv0.6への更新を確認してから使う。
